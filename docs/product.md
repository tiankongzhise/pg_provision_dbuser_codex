# PostgreSQL 用户开通工具产品文档

## 1. 产品目标

本工具用于在本地浏览器中完成 PostgreSQL 业务用户和专属数据库的标准化开通。管理员通过 `.env` 中配置的登录账号进入系统，填写目标用户名、数据库名和业务密码，先预览即将执行的 SQL，再确认执行。

产品第一版聚焦单个 PostgreSQL 目标环境，不提供多环境切换、不覆盖已有对象、不自动回滚已创建对象，优先保证流程清晰、误操作风险低、执行结果可追溯。

## 2. 目标用户

- 数据库管理员：需要快速创建业务库、业务用户并补齐常用权限。
- 开发负责人：需要在开发或测试环境中按统一模板创建 PostgreSQL 访问账号。
- 运维人员：需要通过本地工具减少重复执行 SQL 时的复制和替换错误。

## 3. 核心流程

1. 管理员启动 Go 程序，浏览器访问 `http://127.0.0.1:8080`。
2. 系统检测登录状态；未登录时跳转到 `/login`。
3. 管理员使用 `.env` 中的 `APP_LOGIN_USER` 和 `APP_LOGIN_KEY` 登录。
4. 管理员填写业务用户名、数据库名和业务用户密码。
5. 管理员也可以点击生成强密码按钮，由系统生成并填入密码框。
6. 管理员提交预览，系统校验输入并生成 SQL 预览草稿。
7. 管理员确认 SQL 无误后点击执行。
8. 系统连接 `.env` 中配置的 PostgreSQL 超级账号，检查用户和数据库是否已存在。
9. 如果用户或数据库已存在，系统停止执行并展示错误。
10. 如果检查通过，系统按固定步骤创建用户、创建数据库并授权。
11. 系统展示每一步执行结果，包含成功步骤、失败步骤和错误信息。

## 4. 页面与交互

### 登录页

- 路径：`GET /login`
- 字段：管理员账号、管理员密钥。
- 行为：登录成功后进入首页；登录失败时留在登录页并展示错误。
- 安全要求：登录密钥不回显，不写入 URL，不记录到页面。

### 首页表单

- 路径：`GET /`
- 字段：业务用户名、数据库名、业务用户密码。
- 行为：支持手动输入业务密码，也支持点击生成强密码。
- 校验：用户名和数据库名只能使用 PostgreSQL 常见安全命名；密码不能为空且长度必须满足最低要求。

### SQL 预览页

- 路径：`POST /preview`
- 内容：展示即将执行的 SQL，包含 `\c {数据库名}` 和 `\c postgres` 以贴近人工执行模板。
- 行为：确认执行时只提交服务端草稿标识，不把业务密码放入隐藏表单字段。

### 执行结果页

- 路径：`POST /execute`
- 内容：展示每个步骤的执行状态和错误信息。
- 行为：如果中途失败，不自动删除已创建的用户或数据库，由管理员人工确认后处理。

## 5. 输入规则

- 用户名：字母或下划线开头，后续允许字母、数字、下划线，最长 63 字符。
- 数据库名：规则同用户名。
- 业务密码：不能为空，最低 12 字符。
- 保留数据库名：`postgres`、`template0`、`template1` 不允许作为业务数据库名。

## 6. PostgreSQL 执行规则

执行顺序固定为：

1. 检查目标用户是否存在。
2. 检查目标数据库是否存在。
3. 创建登录用户。
4. 创建专属数据库，并指定该用户为所有者。
5. 授予该用户连接自己数据库的权限。
6. 连接业务数据库。
7. 授予该用户在 `public` schema 下建表权限。
8. 授予当前所有表的增删改查权限。
9. 授予当前所有序列的使用和查询权限。
10. 设置未来新建表的默认增删改查权限。
11. 设置未来新建序列的默认使用和查询权限。

`CREATE DATABASE` 不在事务中执行。实际程序不会执行 `psql` 的 `\c` 命令，而是通过重新建立到目标数据库的连接完成切库。

## 7. 错误与边界

- 登录失败：展示账号或密钥错误。
- `.env` 缺少必要配置：程序启动失败并输出明确错误。
- 目标用户已存在：停止执行，不跳过、不覆盖。
- 目标数据库已存在：停止执行，不跳过、不覆盖。
- PostgreSQL 连接失败：结果页展示连接失败原因。
- 中途授权失败：展示已完成步骤和失败步骤，不执行自动回滚。

## 8. 安全边界

- 工具仅面向本地使用，默认监听 `127.0.0.1:8080`。
- 真实 `.env` 不提交到 Git。
- 会话 Cookie 使用 `.env` 中的 `APP_SESSION_SECRET` 进行签名。
- SQL 标识符必须安全引用，禁止直接拼接未转义的用户名或数据库名。
- 密码只在登录表单和业务表单中提交，不出现在 URL 中。

## 9. 验收标准

- 管理员可以登录、退出并访问受保护页面。
- 未登录访问首页时会跳转登录页。
- 管理员可以手动输入或生成业务用户密码。
- SQL 预览内容与标准模板一致，并正确替换用户名、数据库名和密码。
- 用户名或数据库名已存在时，系统停止执行并提示。
- 新用户和新库创建成功后，该用户可以连接数据库、创建表并使用自增序列。
- `go test ./...` 通过。
